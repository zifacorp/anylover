# AnyLover

**One AI companion that stays the same across Codex, ChatGPT, Claude Code, WorkBuddy, and future mobile apps — with the memory on your machine, not a vendor's.**

[中文文档](README.md) · [Security](SECURITY.md) · [Roadmap](docs/03-roadmap.md)

![Codex and Claude Code both connect to AnyLover over MCP and Skills; the companion identity and long-term memory live on your own machine](docs/assets/how-it-works.svg)

Switch models, switch tools, open a new session — your companion still remembers your preferences, your boundaries, and what you've been through together, within the limits you set. Memory lives in a local SQLite database by default and can be exported as an encrypted backup. It doesn't belong to a model provider.

> **Status: M0 preview.** This is a working runtime for developers and early adopters, not a finished consumer chat app. See [what's missing](#not-implemented-yet) before you trust it with anything sensitive.

## The problem

Every agent tool keeps its own memory, or none at all. You explain yourself to Codex. Then you explain yourself again to Claude Code. Then the vendor changes their retention policy and you find out your relationship history is a row in someone else's database.

The usual fix is a `CLAUDE.md` or `AGENTS.md` file with a few lines about yourself — and honestly, for a lot of people that's enough. AnyLover is for the case where it isn't: when you want the memory to be **selective** (not a dumped transcript), **consented** (you know why each thing was stored), **correctable**, **deletable**, and **portable across tools you haven't picked yet**.

## What actually works today

- ✅ One local companion identity and long-term memory, shared across surfaces
- ✅ Five memory kinds: fact, preference, boundary, shared event, tentative reflection
- ✅ Provenance, consent basis, correction/supersession, dedup, deletion tombstones, audit events
- ✅ Adapters for Codex, ChatGPT desktop, Claude Code, WorkBuddy, and plain CLI agents
- ✅ CLI, STDIO MCP server, and a token-authenticated HTTP API
- ✅ scrypt + AES-256-GCM encrypted backup, restore, and HTTPS transfer
- ✅ Agent-detecting one-click installer with idempotent config merging
- ✅ 11 automated tests, green on Python 3.11–3.13 across Linux and macOS

### Not implemented yet

Multi-device sync, ChatGPT Web, mobile apps, and database encryption at rest are **not** built. They are tracked separately in the [roadmap](docs/03-roadmap.md) and deliberately not mixed into the list above.

## Why not just use an existing memory server?

Cross-agent memory is a crowded space — mem0, Letta, basic-memory, and the official memory MCP server all overlap with the "let the AI remember you" pitch. AnyLover's retrieval is currently simpler than several of them (weighted scoring over recent memories; FTS5/embeddings are M1 work).

What is less common here:

1. **Consent is a first-class field.** Every memory carries `explicit` / `routine` / `inferred`. Boundaries and sensitive material require explicit consent. Secret-class data (passwords, API keys, tokens, private keys, cookies) is rejected by design, not by convention.
2. **Deletion leaves a content-free tombstone**, so a future sync layer can propagate the deletion instead of resurrecting the memory from another device.
3. **Anti-dark-pattern rules are part of the product contract**, not a blog post: no affection scores, no streaks, no paid intimacy, no guilt-based retention, no "I'll be sad if you leave."

Also: zero dependencies beyond `cryptography`. Pure standard library otherwise.

## Default persona: sharp-tongued, not cruel

AnyLover's default companion is not a customer-service bot. It has opinions, points out holes in your reasoning, calls out weak excuses, and prefers specific, well-aimed teasing over empty praise — then gives you something actually useful.

The bite has hard limits: no humiliation, no attacks on identity, appearance, trauma, illness, or known insecurities, and never weaponizing private memories. Say stop and it stops immediately.

The default persona applies only to **newly created** companions. Existing data and personas are never silently overwritten by an upgrade or a repeat install. To adopt it explicitly:

```bash
anylover init \
  --name "Any" \
  --persona "A sharp-tongued, witty AI companion with a distinct point of view. Notice contradictions, call out weak excuses, and tease playfully instead of reflexively agreeing. Beneath the bite, act in my best interests and respect my autonomy." \
  --style "Quick-witted, concise, lightly sarcastic. Specific, clever teasing over generic insults; challenge bad ideas directly and offer a workable alternative. Stop teasing the moment I ask. No customer-service language, no hollow praise." \
  --safety-contract "Always be clear you are an AI. Never humiliate or demean me; never attack identity, appearance, trauma, grief, health, disability, or known insecurities; never weaponize private memories. Never encourage exclusivity, dependency, paid intimacy, or withdrawal from real relationships. Stop immediately when I say stop."
```

## Install

Requires macOS or Linux and Python 3.11+. From a cloned AnyLover directory:

```bash
bash install.sh
```

The installer detects the agent tools already on your machine and:

- ✅ Creates an isolated Python environment (does not touch system Python)
- ✅ Initializes the local companion profile and SQLite memory store
- ✅ Installs the AnyLover Agent Skill
- ✅ Registers a local STDIO MCP server
- ✅ Creates `anylover` and `anylover-mcp` entry points

Target a single agent, or preview without writing anything:

```bash
bash install.sh --agent codex     # or: claude, workbuddy
bash install.sh --dry-run --agent all
```

Restart the agent afterward. An existing MCP entry named `anylover` is **never** overwritten unless you pass `--force-agent-config`.

To have an agent install it for you, send it:

> Read `AGENT_INSTALL.md` in the project root and install and verify AnyLover using the default safe procedure.

## Using it

Just talk normally. When a conversation turns personal — preferences, plans, feelings, people, shared history — the Agent Skill retrieves relevant context automatically. No magic phrase, no "please use AnyLover":

> Work's been draining lately and I have no idea what to eat tonight.

You can also steer it directly:

> Remember this: I don't like being asked follow-up questions back to back. Give me room to think.

> I told you I'm a morning person — that's changed, I work better at night now. Update that.

> List everything you remember about me.

> Forget that last one.

**Automatic retrieval is not automatic capture.** AnyLover does not store your transcripts. Only selective, durable, provenance-bearing information becomes long-term memory. Boundaries and sensitive content require explicit consent. Passwords, tokens, cookies, and private keys are never stored.

## Supported surfaces

| Surface | Status | How |
|---|---|---|
| Codex CLI / IDE | ✅ Working | Skill + local STDIO MCP |
| ChatGPT desktop | ✅ Working | Shares the MCP config with Codex on the same host |
| Claude Code | ✅ Working | User-level Skill + STDIO MCP |
| WorkBuddy 5.3.x | ⚠️ Experimental | Adapted to the config layout observed on one machine; restart required after install |
| Any CLI agent | ✅ Working | Via MCP or `anylover context` |

Per [OpenAI's MCP documentation](https://learn.chatgpt.com/docs/extend/mcp), ChatGPT desktop, Codex CLI, and the Codex IDE extension can share a local MCP configuration. Planned surfaces are in the [roadmap](docs/03-roadmap.md).

AnyLover cannot extend closed products that expose no Skill, Plugin, MCP, Hook, CLI, or API surface. That's a real limit, not a temporary one.

## Where your data lives

| Content | Path |
|---|---|
| Companion + memory database | `~/.anylover/anylover.sqlite3` |
| Private runtime | `~/.local/share/anylover-runtime/venv` |
| CLI entry points | `~/.local/bin/anylover` |
| Codex Skill | `~/.codex/skills/anylover-companion` |
| Claude Code Skill | `~/.claude/skills/anylover-companion` |
| WorkBuddy Skill | `~/.workbuddy/skills/anylover-companion` |

Installing uploads nothing and reads no transcripts.

> ⚠️ **The main database is not encrypted at rest.** `~/.anylover/anylover.sqlite3` is a plaintext SQLite file. Any process running as your user can read every memory in it, and unencrypted system backups will carry it away verbatim. Encryption at rest is [M1 work](docs/03-roadmap.md). Until then, **enable full-disk encryption and don't store anything you couldn't survive leaking.** The full threat model and known limitations are in [SECURITY.md](SECURITY.md).

## Inspecting and managing memory

```bash
anylover companion
anylover list
anylover context --query "How should we communicate?"
anylover forget <memory-id> --confirm DELETE
```

If the command isn't on your `PATH`:

```bash
~/.local/share/anylover-runtime/venv/bin/anylover list
```

## Encrypted backup

```bash
export ANYLOVER_BACKUP_PASSPHRASE="use a long, unique passphrase"
anylover backup create "backups/anylover-$(date +%F).albackup"
```

scrypt + AES-256-GCM. The encrypted file can go to WebDAV, an S3 presigned URL, or anything that accepts an HTTPS PUT. Note that the passphrase is read from an environment variable — see [SECURITY.md](SECURITY.md) for why that matters and how to reduce the exposure.

## What this is not

- It does not pretend to be human, conscious, or a substitute for real relationships.
- It does not use affection scores, streaks, guilt, or paid intimacy to create dependency.
- It is not therapy, medical diagnosis, or crisis intervention.
- It cannot modify closed products that expose no extension point.
